Python Memory
Management

Reference Counting + Garbage Collector + Object Pools

🔢
Reference Counting
Har object ka reference count track hota hai. Count = 0 → memory free!
▼
How it works
import sys x = [1, 2, 3] # x create kiya → refcount = 1 print(sys.getrefcount(x)) # 2 (x + getrefcount arg) y = x # refcount = 2 z = x # refcount = 3 print(sys.getrefcount(x)) # 4 del y # refcount = 3 del z # refcount = 2 del x # refcount = 0 → FREE!
x ──────→ [1,2,3] (refcount=1) y = x ──→ [1,2,3] (refcount=2) del y ──→ [1,2,3] (refcount=1) del x ──→ [1,2,3] (refcount=0) → FREED
Interview Tip: Reference counting fast hai but circular references handle nahi kar sakta — isliye GC bhi hai.
♻️
Garbage Collector (GC)
Circular references detect karta hai jo ref counting miss karta hai.
▼
Circular Reference Problem
import gc # Circular reference — ref count kabhi 0 nahi hoga! class Node: def __init__(self, val): self.val = val self.next = None a = Node(1) b = Node(2) a.next = b # a → b b.next = a # b → a (CIRCULAR!) del a, b # refcount > 0 but unreachable! # GC handles this! gc.collect() # manual GC trigger print(gc.get_count()) # (gen0, gen1, gen2) print(gc.get_threshold()) # (700, 10, 10)
Generational GC
Generation 0 → Naye objects (frequent collection) Generation 1 → Survived gen0 (less frequent) Generation 2 → Long-lived objects (rare collection) Naya object → Gen0 Gen0 survive → Gen1 Gen1 survive → Gen2 Gen2 = permanent tak
Warning: GC disable karna risky hai — memory leak ho sakta hai. Sirf performance critical sections mein use karo.

Object Interning & Memory Pools
Python small integers aur short strings cache karta hai performance ke liye.
▼
Integer Caching (-5 to 256)
# Small integers cached hain! a = 100; b = 100 print(a is b) # True ← same object! a = 257; b = 257 print(a is b) # False ← cache ke bahar! # String interning s1 = "hello" s2 = "hello" print(s1 is s2) # True ← interned! s3 = "hello world" # space wali strings not always interned s4 = "hello world" print(s3 is s4) # Maybe False # Manual intern import sys s5 = sys.intern("hello world") s6 = sys.intern("hello world") print(s5 is s6) # True
Shallow vs Deep Copy
import copy original = [[1, 2], [3, 4]] # Assignment — same object! ref = original ref[0][0] = 99 print(original) # [[99,2],[3,4]] ← changed! # Shallow copy — new outer, same inner sh = copy.copy(original) sh[0][0] = 0 print(original) # [[0,2],[3,4]] ← inner changed! # Deep copy — completely independent dp = copy.deepcopy(original) dp[0][0] = 100 print(original) # unchanged ✅
Interview Tip: = is reference, copy() is shallow, deepcopy() is full independence. Common bug source in interviews!
🗑️
Memory Optimization Tips
__slots__, generators, weakref se memory bachao.
▼
__slots__ — 30-50% memory save
import sys class Normal: def __init__(self, x, y): self.x = x; self.y = y class Slotted: __slots__ = ('x', 'y') def __init__(self, x, y): self.x = x; self.y = y n = Normal(1, 2) s = Slotted(1, 2) print(sys.getsizeof(n.__dict__)) # ~232 bytes print(sys.getsizeof(s)) # ~56 bytes — no __dict__!
Generator — O(1) memory
# List — sab ek saath: O(n) memory lst = [x**2 for x in range(1_000_000)] # ~8MB! # Generator — ek ek karke: O(1) memory gen = (x**2 for x in range(1_000_000)) # ~120 bytes! # Same result, 99% less memory! total = sum(x**2 for x in range(1_000_000))
Interview Questions
Python memory management kaise kaam karta hai? ▼
Python do mechanisms use karta hai: (1) Reference Counting — har object ka refcount track hota hai, 0 hote hi free hota hai. (2) Generational Garbage Collector — circular references ke liye jo ref counting miss karta hai. Gen 0, 1, 2 mein objects organize hote hain.
Shallow copy aur deep copy mein kya fark hai? ▼
copy.copy() = naya outer object, same inner objects (mutable inner change hoga dono mein). copy.deepcopy() = completely independent copy — kuch bhi change karo, original safe. Assignment (=) = sirf reference copy, same object.
Python mein integer caching kya hota hai? ▼
CPython -5 se 256 tak ke integers cache karta hai. Isliye a = 100; b = 100; a is b → True. Lekin a = 257; b = 257; a is b → False. Yeh optimization hai — Python naye object nahi banata baar baar.
__slots__ kab aur kyon use karein? ▼
Jab lakhon objects banana ho — __slots__ __dict__ replace karta hai fixed array se. 30-50% memory save hoti hai, attribute access bhi faster hota hai. Game development, data processing mein use karo.

Thread Basics
Ek process ke andar multiple threads — shared memory.
▼
Basic Thread
import threading import time def download(url, duration): print(f"Starting: {url}") time.sleep(duration) # I/O simulate print(f"Done: {url}") # Sequential — slow (3+2+1 = 6 seconds) download("file1", 3) download("file2", 2) download("file3", 1) # Threaded — fast (max = 3 seconds!) threads = [] for url, dur in [("file1",3),("file2",2),("file3",1)]: t = threading.Thread(target=download, args=(url, dur)) threads.append(t) t.start() for t in threads: t.join() # sab complete hone ka wait karo print("All downloads complete!")
Best for: I/O bound tasks — file reading, API calls, database queries, network requests.
NOT for: CPU bound tasks — GIL ki wajah se multiple threads ek hi core use karte hain.

Thread Safety — Lock, RLock, Semaphore
Shared data ko protect karo race conditions se.
▼
Race Condition Problem
# Race condition — counter wrong ho sakta hai! counter = 0 def increment(): global counter for _ in range(100_000): counter += 1 # NOT atomic! Race condition! t1 = threading.Thread(target=increment) t2 = threading.Thread(target=increment) t1.start(); t2.start() t1.join(); t2.join() print(counter) # Should be 200000 but might not be!
Lock se Fix karo
lock = threading.Lock() counter = 0 def safe_increment(): global counter for _ in range(100_000): with lock: # acquire + release automatic counter += 1 # ✅ thread safe! # Semaphore — limited concurrent access sem = threading.Semaphore(3) # max 3 threads at once def limited_task(n): with sem: print(f"Thread {n} working") time.sleep(1) # Event — thread coordination event = threading.Event() def waiter(): print("Waiting for signal...") event.wait() # block karo jab tak signal nahi print("Signal received!") threading.Thread(target=waiter).start() time.sleep(2) event.set() # signal do!

ThreadPoolExecutor
Thread pool — modern aur clean way to manage threads.
▼
ThreadPoolExecutor — Production Way
from concurrent.futures import ThreadPoolExecutor, as_completed import time def fetch_url(url): time.sleep(1) # API call simulate return f"Data from {url}" urls = ["api1.com", "api2.com", "api3.com", "api4.com"] # map — same order, blocking with ThreadPoolExecutor(max_workers=4) as executor: results = list(executor.map(fetch_url, urls)) print(results) # Total time: ~1s instead of 4s! # submit — individual futures, results as they complete with ThreadPoolExecutor(max_workers=4) as executor: futures = {executor.submit(fetch_url, url): url for url in urls} for future in as_completed(futures): url = futures[future] result = future.result() print(f"{url}: {result}")
Interview Tip: ThreadPoolExecutor prefer karo manual Thread management se — cleaner, safer, context manager support.
Interview Questions
Thread kya hota hai? Process se kya fark? ▼
Thread = process ke andar lightweight execution unit. Same memory share karte hain. Process = independent, alag memory space. Threads faster create hote hain, less memory. Process isolated, safer.
Race condition kya hai? Kaise fix karein? ▼
Race condition = do threads same data simultaneously modify karein, unpredictable result. Fix: threading.Lock() use karo — sirf ek thread ek waqt critical section execute kare. with lock: context manager se automatic acquire/release.
Daemon thread kya hota hai? ▼
Daemon thread background mein chalta hai. Jab main thread khatam hota hai, daemon threads bhi khatam ho jaate hain automatically. Set karo: t.daemon = True. Background tasks, logging ke liye use hota hai.

Process Communication — Queue, Pipe, Shared Memory
Processes alag memory mein hain — data share karne ke special ways.
▼
Queue — Safe Communication
from multiprocessing import Process, Queue def producer(q): for i in range(5): q.put(i) print(f"Produced: {i}") def consumer(q): while True: item = q.get() if item is None: break print(f"Consumed: {item}") if __name__ == "__main__": q = Queue() p = Process(target=producer, args=(q,)) c = Process(target=consumer, args=(q,)) p.start(); c.start() p.join() q.put(None) # sentinel — consumer stop karo c.join()
Shared Memory
from multiprocessing import Value, Array # Shared integer counter = Value('i', 0) # 'i' = integer type # Shared array shared_arr = Array('d', [1.0, 2.0, 3.0]) # 'd' = double def update(val, arr): with val.get_lock(): # thread/process safe! val.value += 1
Interview Questions
Multiprocessing vs Threading kab use karein? ▼
Threading: I/O bound tasks (file, network, DB) — GIL I/O wait pe release hota hai. Multiprocessing: CPU bound tasks (calculations, ML) — separate processes, no GIL. Rule: slow I/O → threads. Heavy CPU → processes.
if __name__ == "__main__" kyun zaroori hai multiprocessing mein? ▼
Windows pe multiprocessing spawn method use karta hai — naya process script ko import karta hai. Bina guard ke, infinite loop mein naye processes bante rehte hain. Linux pe fork use hota hai — less critical but best practice hai.
Processes ke beech data share kaise karte hain? ▼
3 ways: (1) Queue — safe, FIFO communication. (2) Pipe — fast, two-way communication. (3) Value/Array — shared memory, lock se protect karo. Queue safest hai production mein.
GIL

Global Interpreter
Lock (GIL)

CPython ka controversial feature — samjho kyun hai aur kab matter karta hai

🔒
GIL Kya Hai?
Ek mutex jo ensure karta hai ek waqt mein sirf ek thread Python bytecode execute kare.
▼
GIL — Global Interpreter Lock Thread 1 ──→ GIL acquire karo ──→ Python bytecode execute Thread 2 ──→ GIL ka wait karo... (blocked!) Thread 3 ──→ GIL ka wait karo... (blocked!) Thread 1 GIL release ──→ Thread 2 acquire ──→ execute Thread 1, 3 wait... CPU bound: Only 1 thread runs at a time! I/O bound: GIL released during I/O wait ✅
GIL ka Effect
import threading, time def cpu_work(n): return sum(x**2 for x in range(n)) # Sequential start = time.time() cpu_work(10**7) cpu_work(10**7) print(f"Sequential: {time.time()-start:.2f}s") # ~4s # Threaded — GIL ki wajah se NO SPEEDUP! start = time.time() t1 = threading.Thread(target=cpu_work, args=(10**7,)) t2 = threading.Thread(target=cpu_work, args=(10**7,)) t1.start(); t2.start() t1.join(); t2.join() print(f"Threaded: {time.time()-start:.2f}s") # ~4s (same!) # Solution: Multiprocessing for CPU bound! from multiprocessing import Pool start = time.time() with Pool(2) as p: p.map(cpu_work, [10**7, 10**7]) print(f"Multiprocess: {time.time()-start:.2f}s") # ~2s!
❓
GIL Kyun Hai?
CPython memory management thread-safe nahi hai — GIL usse protect karta hai.
▼
GIL ka Reason: CPython → Reference counting se memory manage Reference counting → NOT thread safe! Thread 1: refcount = refcount + 1 ← read Thread 2: refcount = refcount + 1 ← read (same value!) Thread 1: store 6 Thread 2: store 6 (should be 7! BUG!) GIL: Ek waqt mein ek thread → refcount safe!
GIL Workarounds
# 1. Multiprocessing — separate processes, no GIL from multiprocessing import Pool # 2. NumPy — C extensions release GIL! import numpy as np arr = np.array(range(10**6)) result = np.sum(arr**2) # GIL released! C speed! # 3. asyncio — single thread, cooperative import asyncio # 4. Cython — Python to C, release GIL # cdef function with nogil: ... # 5. PyPy — JIT compiler, different approach
Interview Tip: GIL sirf CPython mein hai. PyPy, Jython, IronPython mein nahi. Python 3.12+ mein per-interpreter GIL aa raha hai!
📊
GIL aur I/O Bound Tasks
I/O wait ke dauran GIL release hota hai — threading kaam karta hai!
▼
I/O Bound — GIL Release: Thread 1: GIL acquire → network request → GIL RELEASE (waiting) Thread 2: GIL acquire → run! Thread 1: response aaya → GIL acquire → continue Result: True concurrency for I/O! ✅ CPU Bound — GIL Problem: Thread 1: GIL acquire → calculate → calculate → calculate Thread 2: wait... wait... wait... wait... Result: No speedup! Use multiprocessing ❌
Real World Decision
# I/O Bound → Threading ✅ # - REST API calls # - Database queries # - File reading/writing # - Web scraping # CPU Bound → Multiprocessing ✅ # - Image/video processing # - ML model training # - Data transformation # - Mathematical computations # I/O + Scale → asyncio ✅ # - Thousands of concurrent connections # - FastAPI, aiohttp servers # - WebSocket handlers
Interview Questions
GIL kya hai aur Python mein kyun hai? ▼
GIL (Global Interpreter Lock) ek mutex hai jo ensure karta hai ek waqt mein sirf ek thread Python bytecode execute kare. Kyun hai: CPython ka reference counting memory management thread-safe nahi hai — GIL usse protect karta hai. Downside: CPU bound multi-threaded programs slow ho jaate hain.
GIL remove kyun nahi kiya? ▼
GIL remove karna CPython ke entire memory management ko rewrite karna hoga — huge breaking change. Many C extensions GIL assume karte hain. Single-threaded code slow ho jaata. Python 3.12+ mein per-interpreter GIL experiment chal raha hai (PEP 703).
NumPy threading ke saath fast kyun hai? ▼
NumPy C extensions mein likha hai. C code execution ke dauran GIL release kar sakta hai — Py_BEGIN_ALLOW_THREADS. Isliye NumPy operations truly parallel run ho sakte hain multiple threads mein. Yeh GIL bypass karta hai legitimately.

async/await Basics
Coroutines — functions jo pause aur resume ho sakti hain.
▼
Basic async/await
import asyncio # async function = coroutine async def fetch_data(url): print(f"Fetching {url}...") await asyncio.sleep(1) # I/O simulate — yields control! print(f"Done: {url}") return f"Data: {url}" async def main(): # Sequential — slow (2 seconds total) r1 = await fetch_data("api1") r2 = await fetch_data("api2") # Concurrent — fast (1 second total!) r1, r2 = await asyncio.gather( fetch_data("api1"), fetch_data("api2") ) print(r1, r2) asyncio.run(main())
Event Loop Flow: 1. fetch("api1") start → asyncio.sleep → YIELD control 2. fetch("api2") start → asyncio.sleep → YIELD control 3. sleep done → fetch("api1") RESUME 4. sleep done → fetch("api2") RESUME Total time: ~1s (not 2s!)
🔄
Event Loop Deep Dive
Single thread mein concurrency kaise hoti hai.
▼
Event Loop Architecture: Event Loop (single thread) │ ├── Task Queue: [task1, task2, task3...] │ ├── Running: task1 execute │ task1 → await I/O → SUSPEND │ task2 → execute │ task2 → await I/O → SUSPEND │ task3 → execute │ └── I/O done → task1 RESUME → task2 RESUME CPU blocking code → event loop block hoga!
Tasks aur gather
async def main(): # gather — concurrent wait results = await asyncio.gather( fetch("url1"), fetch("url2"), fetch("url3") ) # create_task — fire and forget task = asyncio.create_task(fetch("url4")) # kuch aur kaam karo... result = await task # ab result lo # timeout try: result = await asyncio.wait_for(fetch("slow"), timeout=5.0) except asyncio.TimeoutError: print("Request timed out!") # asyncio.wait — more control tasks = [asyncio.create_task(fetch(u)) for u in urls] done, pending = await asyncio.wait( tasks, return_when=asyncio.FIRST_COMPLETED )

Interview Questions
async/await kya hai? Event loop kaise kaam karta hai? ▼
async def se coroutine banti hai. await se coroutine pause hoti hai aur event loop dusra kaam karta hai. Event loop single-threaded hai — cooperative multitasking. I/O wait pe yield karo → dusra coroutine run karo → I/O done → resume.
asyncio.gather vs asyncio.wait kya hai? ▼
gather() — sab tasks concurrently run, sab complete hone ka wait, results same order mein. wait() — more control, FIRST_COMPLETED, ALL_COMPLETED options, done aur pending sets milte hain. Production mein gather() simpler hai mostly.
async code mein CPU blocking kaise handle karein? ▼
loop.run_in_executor() use karo. CPU heavy work ko ProcessPoolExecutor mein run karo — event loop block nahi hoga. Threading ke saath bhi kar sakte hain I/O ke liye. Kabhi bhi CPU intensive code directly async function mein mat likho.
Threading vs asyncio kab choose karein? ▼
asyncio: Thousands of concurrent I/O connections, single-threaded simplicity, modern Python (FastAPI). Threading: Legacy code integration, blocking libraries jo async support nahi karte, simpler mental model. asyncio more scalable hai for high concurrency.

Top Interview Questions
Python mein concurrency achieve karne ke kya ways hain? ▼
3 ways: (1) Threading — same process, shared memory, I/O bound ke liye, GIL affected. (2) Multiprocessing — separate processes, separate memory, CPU bound ke liye, no GIL. (3) asyncio — single thread, cooperative multitasking, high concurrency I/O ke liye.
FastAPI itna fast kyun hai? ▼
FastAPI async/await use karta hai. Ek request I/O wait pe hoti hai → event loop dusri request serve karta hai. Yeh single thread mein thousands of concurrent requests handle kar sakta hai. Uvicorn ASGI server bhi async hai. Flask synchronous hai isliye slower for I/O bound workloads.
Deadlock kya hai? Kaise avoid karein? ▼
Deadlock = do threads ek dusre ke lock ka wait kar rahe hain — dono stuck! Example: Thread A has Lock1, wants Lock2. Thread B has Lock2, wants Lock1. Avoid: Always same order mein locks acquire karo. Timeout use karo: lock.acquire(timeout=5). RLock use karo reentrant code ke liye.
Coroutine aur Thread mein kya fark hai? ▼
Thread: OS level, preemptive scheduling (OS decide karta hai kab switch karna hai), true parallel possible, context switch expensive. Coroutine: Application level, cooperative scheduling (code decide karta hai kab yield karna hai), single thread, context switch very cheap. 1000 threads = memory hog. 1000 coroutines = fine!

Parallelism

🔀
Concurrency vs Parallelism — Core Difference
Concurrency = dealing with multiple things. Parallelism = doing multiple things simultaneously.
▼
CONCURRENCY — ek chef, multiple dishes Chef → chop vegetables → (wait for water to boil) → stir sauce → (wait) → plate dish Single worker, multiple tasks, interleaved PARALLELISM — multiple chefs, multiple dishes Chef1 → full dish 1 (simultaneously) Chef2 → full dish 2 (simultaneously) Multiple workers, truly simultaneous You can have concurrency WITHOUT parallelism! asyncio = concurrent but NOT parallel (single thread) multiprocessing = both concurrent AND parallel
Python mein kya kya hai
# CONCURRENCY only (single thread, interleaved) import asyncio # asyncio — concurrent but single threaded # ek waqt mein sirf ek coroutine "runs" # but quickly switch karta hai # CONCURRENCY + some parallelism (OS decides) import threading # threads concurrent hain # CPU bound pe: GIL ki wajah se NOT truly parallel # I/O bound pe: GIL release → some parallelism # TRUE PARALLELISM (multiple CPU cores) import multiprocessing # truly parallel — separate processes # multiple CPU cores simultaneously use karo
Interview Answer: "Concurrency is about structure — dealing with multiple things. Parallelism is about execution — doing multiple things at once. asyncio gives concurrency, multiprocessing gives parallelism."

Race Conditions, Deadlocks, Starvation
Concurrency ke common problems aur solutions.
▼
Race Condition
import threading balance = 1000 lock = threading.Lock() # ❌ Race condition — without lock def withdraw_unsafe(amount): global balance if balance >= amount: # Gap yahan! Another thread can run here! balance -= amount # ✅ Thread safe — with lock def withdraw_safe(amount): global balance with lock: # atomic operation! if balance >= amount: balance -= amount return True return False
Deadlock
import threading lock1 = threading.Lock() lock2 = threading.Lock() # ❌ Deadlock! def task_a(): with lock1: with lock2: # waits for lock2 print("A done") def task_b(): with lock2: with lock1: # waits for lock1 — DEADLOCK! print("B done") # ✅ Fix: Always acquire locks in same order! def task_a_safe(): with lock1: # always lock1 first with lock2: print("A done") def task_b_safe(): with lock1: # always lock1 first with lock2: print("B done") # Timeout se deadlock detect karo: acquired = lock1.acquire(timeout=5) if not acquired: print("Possible deadlock!")
Deadlock Rule: Hamesha same order mein locks acquire karo. Ya timeout use karo: lock.acquire(timeout=5).

Interview Questions
Concurrency aur Parallelism mein kya fark hai? ▼
Concurrency: Multiple tasks ko deal karna — ek thread multiple tasks ke beech switch karta hai (asyncio). Parallelism: Multiple tasks literally same time chalte hain (multiprocessing — multiple CPU cores). Concurrency structure ke baare mein hai, parallelism execution ke baare mein.
Deadlock kya hai? Kaise prevent karein? ▼
Deadlock = do ya zyada threads ek dusre ke lock ka indefinitely wait karein. Prevention: (1) Always same order mein locks acquire karo. (2) lock.acquire(timeout=N) use karo. (3) RLock for recursive code. (4) Lock-free data structures use karo jahan possible ho.
Lock aur Semaphore mein kya fark hai? ▼
Lock = binary mutex — sirf ek thread access kar sakta hai. Semaphore = counter — N threads simultaneously access kar sakte hain. Use: Lock = critical section. Semaphore = connection pool, rate limiting (e.g., max 5 DB connections).

Interview Questions
Context manager kya hai? __enter__ aur __exit__ explain karo. ▼
Context manager ek object hai jo with statement ke saath use hota hai. __enter__: with block start pe call hota hai, return value as variable mein milti hai. __exit__: block end pe call hota hai — chahe exception aaye ya nahi. Resource cleanup guarantee karta hai.
__exit__ mein True return karna kya karta hai? ▼
__exit__ se True return = exception suppress ho jaati hai (ignore). False (ya None) return = exception normally propagate hoti hai. Mostly False return karo — exceptions silently swallow karna dangerous hai.
@contextmanager vs class-based kaunsa better hai? ▼
Simple cases ke liye @contextmanager better — kam code, readable. Complex cases (state maintain karna, inheritance) ke liye class-based better. @contextmanager mein yield ke pehle = __enter__, baad mein = __exit__. try/finally use karo cleanup guarantee ke liye.

Interview Questions
Metaprogramming kya hai Python mein? ▼
Metaprogramming = code jo dusre code ko read, generate ya modify kare. Python mein: decorators (function behavior modify), descriptors (attribute access control), metaclass (class creation control), __getattr__/__setattr__ (dynamic attributes), AST manipulation (source code transform).
Descriptor protocol kya hai? @property se kya relation? ▼
Descriptor = class with __get__, __set__, __delete__. Attribute access intercept karta hai. @property internally descriptor protocol use karta hai — property object ek descriptor hai. Django models, SQLAlchemy fields sab descriptors hain.
Metaclass kya hai? Kab use karein? ▼
Metaclass = class ki class. type default metaclass hai. Custom metaclass se class creation process control hota hai — class banate waqt methods inject karo, validate karo, register karo. Use karo: ORMs, plugin systems, API frameworks mein. Normal code mein __init_subclass__ simpler alternative hai.
__getattr__ aur __getattribute__ mein kya fark hai? ▼
__getattr__: Sirf tab call hota hai jab attribute normal lookup se nahi mila — missing attributes ke liye. __getattribute__: Hamesha call hota hai — every attribute access pe. __getattribute__ mein super().__getattribute__(name) call karna zaroori hai — warna infinite recursion!
