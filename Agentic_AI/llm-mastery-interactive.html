Embeddings

Token IDs ko high-dimensional vectors mein convert karna. Yahan semantic meaning encode hoti hai — "king - man + woman = queen" wala concept!

Token Embeddings (Lookup Table)

Har token ID ka ek fixed vector hota hai ek badi lookup table mein. GPT-2 mein yeh table 50,257 × 768 = 38.6 million parameters ki hoti hai!

PYTHON
import torch
import torch.nn as nn

vocab_size = 50257    # GPT-2 vocabulary
embed_dim  = 768      # har token = 768 numbers

# Yeh andar se sirf ek badi matrix hai
embedding_table = nn.Embedding(vocab_size, embed_dim)

# "Hello I am" ke token IDs
token_ids = torch.tensor([9906, 358, 1097])

vectors = embedding_table(token_ids)
print(f"Input tokens:  {token_ids.tolist()}")
print(f"Output shape:  {vectors.shape}")  # [3, 768]
print(f"First 5 vals:  {vectors[0][:5].tolist()}")
# [0.23, -0.45, 0.89, 0.12, 0.67]

# Table size = vocab × dim = 50257 × 768 = 38.6M params!
params = vocab_size * embed_dim
print(f"Embedding table params: {params:,}")
Positional Embeddings

"Dog bites man" aur "Man bites dog" — same tokens, alag meaning! Model ko position bhi chahiye. Token embedding + Positional embedding = final input.

PYTHON
import torch, math

def positional_encoding(seq_len, d_model):
    pe = torch.zeros(seq_len, d_model)
    pos = torch.arange(0, seq_len).unsqueeze(1).float()
    div = torch.exp(torch.arange(0, d_model, 2).float() *
                    (-math.log(10000.0) / d_model))
    pe[:, 0::2] = torch.sin(pos * div)
    pe[:, 1::2] = torch.cos(pos * div)
    return pe

# "I love Python" = 3 tokens
token_emb = torch.randn(3, 768)       # lookup table se
pos_emb   = positional_encoding(3, 768) # position se

# Dono add karo — final transformer input!
final_input = token_emb + pos_emb
print(final_input.shape)  # torch.Size([3, 768])

Word2Vec: "bank" ka ek hi vector — river bank ho ya money bank. BERT/GPT: context ke hisaab se alag vector. Yahi modern LLMs ka superpower hai!

PYTHON — Contextual (BERT)
from transformers import BertTokenizer, BertModel
import torch

tokenizer = BertTokenizer.from_pretrained('bert-base-uncased')
model     = BertModel.from_pretrained('bert-base-uncased')

def get_embedding(sentence):
    inputs = tokenizer(sentence, return_tensors='pt')
    with torch.no_grad():
        out = model(**inputs)
    return out.last_hidden_state[0].mean(dim=0)

e1 = get_embedding("I went to the river bank")
e2 = get_embedding("I deposited money at the bank")

sim = torch.nn.functional.cosine_similarity(e1.unsqueeze(0), e2.unsqueeze(0))
print(f"Same word 'bank', diff context sim: {sim.item():.3f}")
# ~0.61 — alag vectors! ✅
Semantic Similarity — RAG ka Core

Sentence embeddings real production mein use hote hain — RAG, semantic search, recommendations. Yahi Stage 2 ka foundation hai!

PYTHON
# pip install sentence-transformers
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer('all-MiniLM-L6-v2')  # 384 dims

    "Python backend development with FastAPI",
    "Building REST APIs using Django",
    "Database optimization in PostgreSQL",
    "I love eating pizza on weekends",
]

query = "How to build APIs in Python"
q_emb = model.encode(query)

def cos_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

scores = [(cos_sim(q_emb, d), docs[i]) for i, d in enumerate(doc_embs)]
for score, doc in sorted(scores, reverse=True):
    print(f"{score:.3f}  — {doc}")

# 0.874  — Building REST APIs using Django ✅
# 0.623  — Database optimization in PostgreSQL

Long Context Strategies

Jab document context se bada ho, toh yeh 3 strategies use karo:

PYTHON
# Strategy 1: Chunking + Retrieval (RAG approach)
def chunk_text(text, chunk_size=500, overlap=50):
    words = text.split()
    chunks = []
    for i in range(0, len(words), chunk_size - overlap):
        chunk = " ".join(words[i:i + chunk_size])
        chunks.append(chunk)
    return chunks

# Strategy 2: Map-Reduce — summarize phir combine
def map_reduce_summarize(long_doc, client):
    chunks = chunk_text(long_doc, chunk_size=1000)

    # MAP: har chunk ko alag summarize karo
    summaries = []
    for chunk in chunks:
        resp = client.chat.completions.create(
            model="gpt-4",
            messages=[{"role": "user",
                       "content": f"Summarize in 2 lines:\n{chunk}"}]
        )
        summaries.append(resp.choices[0].message.content)

    # REDUCE: sab summaries combine karo
    combined = "\n".join(summaries)
    final = client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user",
                   "content": f"Final summary:\n{combined}"}]
    )
    return final.choices[0].message.content
💡 Production Rule: Context window = RAM ki tarah. Zyada text = zyada cost + slow response. Hamesha sirf relevant chunks send karo. RAG isi problem ka solution hai!
Stage 1 · Module 2 · Topic 4

Transformer Architecture

2017 mein "Attention is All You Need" paper ne sab badal diya. Aaj har modern LLM — GPT, Claude, Gemini, LLaMA — transformer pe chhalta hai.

3 Main Components

Transformer ke teen parts hain: (1) Embedding Layer — text ko vectors banata hai, (2) Transformer Blocks — attention + MLP, (3) Output Layer — next token predict karta hai.

PYTHON — Minimal Transformer
import torch
import torch.nn as nn

class MiniTransformer(nn.Module):
    def __init__(self, vocab_size=1000, d_model=256,
                 nhead=4, num_layers=2):
        super().__init__()

        # Step 1: Token Embedding
        self.embedding = nn.Embedding(vocab_size, d_model)

        # Step 2: Transformer Blocks (attention + MLP inside)
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead,
            dim_feedforward=d_model*4, batch_first=True
        )
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers)

        # Step 3: Output — vocab pe probability
        self.output = nn.Linear(d_model, vocab_size)

    def forward(self, token_ids):
        x = self.embedding(token_ids)   # IDs → vectors
        x = self.transformer(x)         # attention process
        x = self.output(x)              # → vocab probabilities
        return x

model = MiniTransformer()
tokens = torch.randint(0, 1000, (1, 10))  # batch=1, seq=10
logits = model(tokens)
print(logits.shape)  # [1, 10, 1000] — har position pe vocab probs
Feed-Forward / MLP Layer

Attention ke baad har token independently ek MLP se guzarta hai. Yahan "factual knowledge" store hoti hai — capital of France = Paris type information.

PYTHON
class FeedForward(nn.Module):
    def __init__(self, d_model=768, expansion=4):
        super().__init__()
        # GPT mein d_model*4 = 4x expansion hai
        self.net = nn.Sequential(
            nn.Linear(d_model, d_model * expansion),
            nn.GELU(),           # activation function
            nn.Linear(d_model * expansion, d_model),
            nn.Dropout(0.1),
        )
        self.norm = nn.LayerNorm(d_model)

    def forward(self, x):
        # Residual connection: x + FFN(x)
        return self.norm(x + self.net(x))

ff = FeedForward()
x = torch.randn(1, 5, 768)  # batch=1, seq=5, dim=768
out = ff(x)
print(out.shape)  # [1, 5, 768] — same shape maintain

Stage 1 · Module 2 · Topic 5

Attention Mechanism

LLM ka core innovation. Har token decide karta hai ki sequence mein kaunse doosre tokens pe "dhyan" dena hai. "Attention is All You Need!"

Q, K, V Matrices — Intuition

Q (Query) = "Main kya dhundh raha hoon?"
K (Key) = "Mere paas kya information hai?"
V (Value) = "Agar relevant hai toh yeh lo."

PYTHON — Self-Attention from Scratch
import torch
import torch.nn as nn
import math

class SelfAttention(nn.Module):
    def __init__(self, d_model=256):
        super().__init__()
        self.d_model = d_model

        # Ek hi input se 3 alag projections
        self.W_q = nn.Linear(d_model, d_model)  # Query
        self.W_k = nn.Linear(d_model, d_model)  # Key
        self.W_v = nn.Linear(d_model, d_model)  # Value
        self.out  = nn.Linear(d_model, d_model)

    def forward(self, x):
        # x shape: [batch, seq_len, d_model]
        Q = self.W_q(x)  # Query matrix
        K = self.W_k(x)  # Key matrix
        V = self.W_v(x)  # Value matrix

        # Attention scores: Q × K^T / sqrt(d_model)
        scores = torch.matmul(Q, K.transpose(-2, -1))
        scores = scores / math.sqrt(self.d_model)

        # Softmax → probabilities (0 to 1, sum=1)
        attn_weights = torch.softmax(scores, dim=-1)

        # Weighted sum of Values
        output = torch.matmul(attn_weights, V)
        return self.out(output), attn_weights

attn = SelfAttention(d_model=256)
x = torch.randn(1, 5, 256)  # 5 tokens
out, weights = attn(x)
print(f"Output: {out.shape}")      # [1, 5, 256]
print(f"Weights: {weights.shape}")  # [1, 5, 5] — har token kisi pe kitna dhyan
Multi-Head Attention

Sirf ek attention head nahi — multiple parallel heads! Har head alag cheez pe dhyan deta hai. Ek head grammar, doosra entities, teesra relationships track kar sakta hai.

PYTHON
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=256, n_heads=8):
        super().__init__()
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads  # 256/8 = 32

        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.out  = nn.Linear(d_model, d_model)

    def split_heads(self, x, batch):
        x = x.view(batch, -1, self.n_heads, self.head_dim)
        return x.transpose(1, 2)  # [batch, heads, seq, head_dim]

    def forward(self, x):
        batch = x.size(0)
        Q = self.split_heads(self.W_q(x), batch)
        K = self.split_heads(self.W_k(x), batch)
        V = self.split_heads(self.W_v(x), batch)

        scores = torch.matmul(Q, K.transpose(-2,-1)) / math.sqrt(self.head_dim)
        weights = torch.softmax(scores, dim=-1)
        out = torch.matmul(weights, V)

        # Sab heads ko wapas merge karo
        out = out.transpose(1, 2).contiguous().view(batch, -1, self.n_heads * self.head_dim)
        return self.out(out)

mha = MultiHeadAttention(d_model=256, n_heads=8)
x = torch.randn(1, 5, 256)
print(mha(x).shape)  # [1, 5, 256]

client = OpenAI(api_key="your-key")

# System prompt = model ko role do

with client.chat.completions.stream(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": system},
        {"role": "user",   "content": "How to handle DB connections in FastAPI?"}
    ]
) as stream:
    for chunk in stream:
        if chunk.choices[0].delta.content:
            print(chunk.choices[0].delta.content, end="", flush=True)

# Error handling — production zaroori
from openai import RateLimitError, APIError
import time

def safe_completion(messages, retries=3):
    for i in range(retries):
        try:
            return client.chat.completions.create(
                model="gpt-4o", messages=messages
            )
        except RateLimitError:
            time.sleep(2 ** i)  # exponential backoff
        except APIError as e:
            print(f"API Error: {e}"); break
Stage 1 · Module 4 · Topic 9

Function Calling

LLM ko tools dena — weather check karo, DB query karo, API call karo. Yeh agentic AI ka foundation hai! Backend developer ke liye bahut familiar concept.

Function Calling — Full Example
PYTHON
from openai import OpenAI
import json
client = OpenAI(api_key="your-key")

# Step 1: Tool define karo (JSON Schema)
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Get current weather for a city",
        "parameters": {
            "type": "object",
            "properties": {
                "city":  {"type": "string", "description": "City name"},
                "units": {"type": "string", "enum": ["celsius", "fahrenheit"]},
            },
            "required": ["city"]
        }
    }
}]

# Step 2: Model se poocho
messages = [{"role": "user", "content": "Mumbai ka weather kya hai?"}]
resp = client.chat.completions.create(model="gpt-4o", tools=tools, messages=messages)

# Step 3: Model ne tool call kiya?
if resp.choices[0].finish_reason == "tool_calls":
    tool_call = resp.choices[0].message.tool_calls[0]
    args = json.loads(tool_call.function.arguments)
    print(f"Tool: {tool_call.function.name}, Args: {args}")
    # Tool: get_weather, Args: {'city': 'Mumbai', 'units': 'celsius'}

    # Step 4: Actual function call karo
    weather_result = {"city": "Mumbai", "temp": 32, "condition": "Humid"}

    # Step 5: Result wapas model ko do
    messages += [
        resp.choices[0].message,
        {"role": "tool", "tool_call_id": tool_call.id,
         "content": json.dumps(weather_result)}
    ]
    final = client.chat.completions.create(model="gpt-4o", messages=messages)
    print(final.choices[0].message.content)
    # "Mumbai mein abhi 32°C hai aur humidity bahut zyada hai."
💡 Backend Dev Advantage: Function calling = REST API call karne jaisa hai! Aapko REST APIs banana aata hai — yahan sirf LLM decide karta hai kaunsi function call karni hai aur aap execute karte ho.

Stage 2 · Module 2

RAG Pipeline — Full Implementation

Retrieval Augmented Generation — LLM ko external knowledge do without fine-tuning. Documents → Embed → Store → Retrieve → Generate!

Complete RAG System
PYTHON
from openai import OpenAI
import chromadb
from sentence_transformers import SentenceTransformer

client = OpenAI(api_key="your-key")
emb_model = SentenceTransformer('all-MiniLM-L6-v2')
db = chromadb.Client()
collection = db.create_collection("knowledge_base")

# STEP 1: Index documents
docs = [
    "FastAPI supports async/await natively for high performance",
    "Use Pydantic models for request/response validation in FastAPI",
    "SQLAlchemy is the most popular ORM for Python databases",
]
collection.add(documents=docs,
               embeddings=emb_model.encode(docs).tolist(),
               ids=[f"doc{i}" for i in range(len(docs))])

# STEP 2: RAG query function
def rag_query(question, n_results=2):
    # Retrieve relevant docs
    q_emb = emb_model.encode([question]).tolist()
    results = collection.query(query_embeddings=q_emb, n_results=n_results)
    context = "\n".join(results['documents'][0])

    # Generate answer with context
    resp = client.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": f"Context:\n{context}\n\nQuestion: {question}"
        }]
    )
    return resp.choices[0].message.content

print(rag_query("How to validate requests in FastAPI?"))

Stage 2 · Module 3

Hybrid Search & Reranking

Semantic search + keyword search = hybrid. Reranking se best results top pe. Production RAG ka must-have!

BM25 + Semantic = Hybrid
PYTHON
# pip install rank_bm25 sentence-transformers
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer, CrossEncoder
import numpy as np

docs = ["FastAPI async endpoints", "PostgreSQL indexing",
        "Docker deployment guide", "FastAPI database connections"]

# BM25 — keyword based
bm25 = BM25Okapi([d.split() for d in docs])

# Semantic — embedding based
sem_model = SentenceTransformer('all-MiniLM-L6-v2')
doc_embs = sem_model.encode(docs)

query = "FastAPI database"
bm25_scores = np.array(bm25.get_scores(query.split()))
q_emb = sem_model.encode(query)
sem_scores = np.array([np.dot(q_emb, d) / (np.linalg.norm(q_emb)*np.linalg.norm(d)) for d in doc_embs])

# Combine: 0.5 * BM25 + 0.5 * Semantic
hybrid = 0.5*(bm25_scores/bm25_scores.max()) + 0.5*sem_scores
ranked = sorted(zip(docs, hybrid), key=lambda x: x[1], reverse=True)
for doc, score in ranked:
    print(f"{score:.3f} — {doc}")

Pura model train karna bahut expensive hai. LoRA sirf small adapter matrices train karta hai — 100x kam VRAM mein fine-tune karo!

QLoRA Fine-Tuning
PYTHON
# pip install transformers peft trl bitsandbytes
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model
import torch

# 4-bit quantization — QLoRA
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Meta-Llama-3-8B",
    quantization_config=bnb_config, device_map="auto"
)

# LoRA adapter config
lora_config = LoraConfig(
    r=16,              # rank — smaller = fewer params
    lora_alpha=32,     # scaling factor
    target_modules=["q_proj", "v_proj"],  # which layers
    lora_dropout=0.05,
    task_type="CAUSAL_LM"
)

peft_model = get_peft_model(model, lora_config)
peft_model.print_trainable_parameters()
# trainable params: 3,407,872 || all params: 8,033,669,120
# trainable%: 0.04%  ← sirf 0.04% params train karte hain!

Stage 4 · Module 1

LangGraph — State Machines & Graph Workflows

Complex multi-step agents build karo state machines se. Conditional routing, loops, parallel execution — sab possible!

Basic LangGraph Agent
PYTHON
from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated
import operator

class AgentState(TypedDict):
    messages: Annotated[list, operator.add]
    next_step: str

def llm_node(state):
    # LLM call — decide kya karna hai
    response = "I need to search for this information"
    return {"messages": [response], "next_step": "search"}

def search_node(state):
    # Tool use — web search karo
    result = "Found: FastAPI 0.104.1 released"
    return {"messages": [result], "next_step": "end"}

def router(state):
    return state["next_step"]  # "search" ya "end"

# Graph build karo
graph = StateGraph(AgentState)
graph.add_node("llm", llm_node)
graph.add_node("search", search_node)
graph.set_entry_point("llm")
graph.add_conditional_edges("llm", router, {"search": "search", "end": END})
graph.add_edge("search", END)

app = graph.compile()
result = app.invoke({"messages": ["What is FastAPI latest version?"], "next_step": ""})
print(result["messages"])

# Cost tracking manual
from openai import OpenAI
client = OpenAI()

class CostTracker:
    total_tokens = 0
    total_cost_usd = 0.0

    def track(self, usage, model="gpt-4o"):
        prices = {"gpt-4o": (5, 15)}  # per 1M tokens in/out
        inp, out = prices.get(model, (5, 15))
        cost = (usage.prompt_tokens * inp + usage.completion_tokens * out) / 1_000_000
        self.total_tokens += usage.total_tokens
        self.total_cost_usd += cost
        print(f"This call: ${cost:.4f} | Total: ${self.total_cost_usd:.4f}")

tracker = CostTracker()
resp = client.chat.completions.create(model="gpt-4o",
    messages=[{"role": "user", "content": "Hello!"}])
tracker.track(resp.usage)
